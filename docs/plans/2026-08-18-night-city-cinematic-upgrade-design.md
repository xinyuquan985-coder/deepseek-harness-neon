# 夜之城电影级视觉升级设计

## 目标

在现有 DeepSeek Harness 三工作台、辩论模式、错峰模式、语音输入和设置能力上做增量升级。功能、插槽、状态派生、左右对话结构、审批权限、文件操作和现有导航保持不变。A/B/C 仍由真实会话状态自动派生，不新增手动主题或工作台开关。

视觉目标是原创的近未来夜城行动终端：危险、精密、具有角色身份感，但不复制任何商业游戏的角色、标识、字体或界面资产。正式 A/B/C 设计稿继续定义构图、信息密度和角色位置，本次升级负责增加材质、光影、立绘、状态反馈和运动层级。

## 方案比较

### 方案一：仅 CSS 表面强化

增加渐变、阴影、扫描线和发光。实现快、体积小，但人物仍像小图标，无法获得用户要求的游戏 CG 角色感；继续叠加 CSS 也会使所有区域同时发光，缺乏视觉主次。

### 方案二：整页重绘或大图切片

将面板、边框和背景大量栅格化。静态截图可以很华丽，但响应式、真实数据长度、交互状态和主题维护都会变脆，也容易破坏现有功能，是本次明确不采用的路线。

### 方案三：分层混合系统（采用）

原创高分辨率人物立绘负责身份与情绪；CSS 变量和伪元素负责金属、玻璃、碳纤维、网格与灯带；动画只响应真实运行、选中、警告、悬停和视图切换状态。它兼顾最大视觉表现、可维护性和功能安全。

## 视觉系统

### 空间与材质

页面底层由三层组成：深蓝黑城市雾化渐变、低对比电路网格、极弱的纵向玻璃反射。侧栏是磨砂碳纤维，主对话区是低反射深色玻璃，右侧任务区是更硬朗的工业面板。不同层靠亮度与材质区分，而不是继续增加边框数量。

青色表示在线与数据通路，黄色表示当前任务与主操作，绿色表示完成，红色只表示风险、失败和待审批。文字区不使用持续抖动、闪烁或高强度辉光，保证长文本、代码和轨迹数据仍可阅读。

面板保留用户确认的几何规则：右侧执行清单为方角矩形；人物头像为 82×80 单根平斜角框，头像在消息框外；用户在右、AI 在左，网络行者图像朝向 AI；不同角色只更换人物内容和色彩身份，不改变头像尺寸或边框结构。

### 人物与身份

生成六个原创角色锚点：网络行者、Blackwall AI、策划代理、研究代理、编码代理、审核代理。画面采用电影级半身近景、真实皮肤与织物、细密义体结构、单一主色轮廓光和干净深色背景。角色之间共享镜头距离、头肩比例、锐度和光比，使 A/B/C/辩论模式切换时保持同一产品世界观。

Blackwall AI 使用冷青色数字皮肤和微弱数据裂纹；网络行者使用暖黄边缘光与黑色战术织物；策划/研究/编码/审核分别使用黄蓝、冰青、危险红和冷白青作为身份色。人物图片不含文字、商标、水印和额外 UI 边框，外框由代码统一绘制。

### 动效语言

动效遵循“状态发生才运动”。运行中的任务显示沿边移动的能量脉冲；当前选择显示一次快速光扫并保持稳定内辉光；工具完成只触发短促绿色确认；审批使用低频红色呼吸；角色在线状态使用微弱雷达环；视图切换使用 160–220ms 的横向折射过渡。

背景只保留非常慢的城市雾与网格视差，扫描线透明度保持低于正文对比。悬停只抬升 1–2px 并提高局部高光。`prefers-reduced-motion` 下停用光扫、视差、脉冲和位移动画，只保留静态颜色与轮廓。

## 各工作台升级

- A 对话：强化角色主次、消息玻璃层、工具调用的能量接入线、底部作战指令台和任务栏状态灯。
- B 执行：终端获得 CRT 玻璃、代码差异热区、完成态电流扫过和更清晰的文件账本层级；对话仍保持用户右、AI 左。
- C 轨迹：未选事件时账本占满可用宽度；选中事件后才出现左右分栏。事件类型使用独立图形与色彩，当前路径用数据线路连接到协作角色。
- 辩论：正反双方保留完整流程与双栏布局，角色卡增加独立立绘和阵营光；裁判处于视觉中轴，但不改动真实裁决状态。

## 安全边界与验收

先写测试再实现。测试覆盖轨迹详情开关布局、头像几何、角色朝向、方角任务卡、状态类名、减少动效和现有功能入口。实现优先落在 `ui-theme` 的共享语义变量和效果层，各功能包只消费角色色与真实状态，不引入新的业务订阅或硬编码假数据。

验证顺序为聚焦组件测试、相关 TypeScript、客户端 bundle、生产 Web 构建、真实 host-backed A/B/C/辩论浏览器验收。保留当前 `127.0.0.1:3080` 服务，不使用裸 Vite，不停止原进程。最终交付 1920×1080 A/B/C 与辩论截图、Git 提交号和仍存在的偏差清单。
