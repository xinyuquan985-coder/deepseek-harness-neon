# Cyberpunk Three-Workbench UI Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Upgrade the existing Cyber theme into the three approved, real-capability workbenches: A default conversation, B code execution, and C multi-agent trajectory.

**Architecture:** Keep the existing plugin/slot architecture and the built-in `cyber` theme as the single design-token owner. Add view-aware workbench presentation through additive conversation/detail slots and a focused client-only workbench package; do not replace the Agent loop, invent backend state, or create a parallel application shell. **Tech Stack:** TypeScript 6, React 18, CSS Modules, Cordis client plugins, DeepSeek Harness slot/runtime stores, Vitest, Playwright web snapshots, `dsh web` live acceptance.

## 2. State-to-screen routing

Do not introduce a fake user-selectable “A/B/C mode”. Derive the workbench from real UI state:

```ts
export type WorkbenchKind = 'conversation' | 'code' | 'trajectory'

export function deriveWorkbenchKind(input: {
  activeView: string
  currentTurnHasCodeMutation: boolean
}): WorkbenchKind {
  if (input.activeView === 'trajectory') return 'trajectory'
  return input.currentTurnHasCodeMutation ? 'code' : 'conversation'
}
```

`currentTurnHasCodeMutation` must be derived from settled/running tool nodes already present in the current conversation snapshot. Treat filesystem writes/edits, patch/diff results and terminal/code-runtime calls as code activity. Ordinary search/read/tool use remains A. Keep the classifier pure, tested, and conservative: unknown tools do not force B.

Right-panel content follows the derived kind:

- A: mission goal/todo, queue, background jobs, subagents, deliverables and compact role/model/context facts.
- B: files modified in the current turn, diff totals when available, produced files, terminal/code tool status, queued command and execution plan.
- C: subagent roster, background jobs, current trajectory selection/request, approval state and current-turn outputs.

Selecting a concrete tool call still takes precedence and shows the existing full Tool Details panel. Closing tool details returns to the overview; it must not collapse the entire right rail.

## 3. Acceptance criteria

### Functional

- All existing chat, tool, file-open, stop, retry, approval, question, plan, model, permission, voice, off-peak, debate, subagent and trajectory interactions still work.
- No data is generated solely for presentation. Empty sections collapse rather than showing invented rows.
- Right-rail actions call existing services (`ctx.layout`, session/subagent/job/workspace actions); no duplicate RPC layer.
- A switches to B only when the current turn contains real code mutation/execution evidence. The trajectory tab always produces C.
- Tool selection overrides the overview and Close returns to the correct A/B/C overview.
- The composer retains DOM identity across tab/session/workbench changes so drafts, focus and attachments survive.

### Visual

- At 1920×1080, composition closely matches the approved reference for each screen.
- Center text width remains readable; the right rail concedes/collapses before the center drops below the existing `CENTER_MIN` contract.
- Yellow marks primary/current action, cyan marks system/success/information, magenta/red marks risk/error/opposition only.
- Scanlines and glow never reduce content contrast; no continuous high-amplitude animation.
- Keyboard focus is visible; all icon-only actions have accessible names; WCAG AA text contrast is retained.
- At 1366px the inspector may narrow; below the existing concession threshold it closes cleanly without horizontal page scrolling.

### Verification

- Targeted component suites pass after every task.
- `test:gui` is run before delivery; unrelated dirty-tree failures are recorded, not “fixed” outside scope.
- A deterministic host-backed web scenario covers A/B/C and produces snapshots.
- Final acceptance uses a real `dsh web` host and the in-app browser, with console errors checked and screenshots compared against all three approved references.
