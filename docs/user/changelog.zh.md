## 更新之后的会话

较早构建以格式版本 0 存下的会话可以在这个构建中打开。读取方在内存中转换已退役的记录，不改磁盘上的文件。

reason 为 `fallback` 的 `request/header`，只要该请求头写明了提供方和模型，就会变成当前的完整快照。日志中的第一份快照使用 reason `initial`。此后的快照使用 `change`。

已经携带完整请求头的 `request/header-delta` 会变成同一种快照。不完整的 delta 不会被重新应用。读取视图会重复已经生效的请求头。日志里还没有请求头时，它会重复已经生效的 plan 状态，因此周围的消息仍然可以加载。

`mode/set` 记录会变成 `plan/mode`。名称 `plan` 为激活。其他名称均为未激活。

较新 harness 写出的日志仍然无法打开。错误会说明这个方向；对 JSONL 日志，还会给出原始文件路径。

新追加一种已退役类型的事件仍然会失败。schema 版本不是这个构建的 schema 版本的 SQLite 数据库仍然无法打开。默认组合把会话存成 JSONL。
