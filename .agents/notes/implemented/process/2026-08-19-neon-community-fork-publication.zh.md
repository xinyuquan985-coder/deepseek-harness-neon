# Agent Note: Neon 社区分支发布

Status: implemented

[English](2026-08-19-neon-community-fork-publication.md) | 中文

## 问题

如果把本地 Neon 工作台开发成果作为普通的 DeepSeek Harness 副本发布，会让社区分支看起来像 DeepSeek 官方版本；如果直接推送当前工作目录，还可能暴露本地提交邮箱元数据、含本机路径的快照、运行目录或日志。上游 Issue 生命周期自动化还依赖组织持有的凭据，这些凭据在社区分支中既不可用，也不应使用。

## 决策

公开仓库使用 Neon Harness 名称，并明确说明它是 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness) 的非官方社区分支；同时保留上游提交历史、MIT 许可证、第三方声明、包名、架构文档与源码署名。该分支不声明与 DeepSeek 存在隶属、合作或官方背书关系。

首次 Neon 改动以一个经过脱敏的提交发布在上游默认分支之上。发布提交使用 GitHub `noreply` 地址，排除包含本机路径的截图，替换可评审文本快照中的本地路径，并忽略仓库根目录下的运行目录和日志。原本地 worktree 及其未提交文件不进入发布分支。

面向分支的 README 与安全指南指向本仓库自己的 Issues、Discussions、私密漏洞报告和源码检出地址。上游组织专用的 Issue 策略任务只在上游仓库运行；普通构建与测试工作流继续供社区分支使用。

## 曾考虑的替代方案

**原样推送七个本地提交。** 否决，因为提交作者元数据与两项已提交产物保留了本机信息；即使后续提交删除可见文本，这些信息仍会留在历史中。

**移除上游历史与署名。** 否决，因为本分支依赖上游架构、包、文档与许可证链；保留来源既准确，也便于维护。

**立即重命名全部 `@deepseek-ai/*` 包。** 否决，因为本次发布改变社区产品身份，不改变内部包兼容接口。包命名空间迁移需要单独的全仓库决策。

**在分支中继续启用上游 Issue 自动化。** 否决，因为它面向组织持有的项目和 GitHub App 凭据；跳过这些任务可以避免虚假失败，同时不会削弱分支的普通 CI。

## 后果

公开仓库获得独立的社区身份，同时保留上游来源；首个 Neon 提交不包含已知密钥、个人路径、运行状态或公开作者邮箱。合并提交意味着公开分支主动放弃七个本地提交的开发顺序，但源码结果与已实现 Agent Note 仍可评审。未来通过 `upstream` remote 同步上游，而社区 Release、Issues 与 Discussions 均归 Neon 仓库所有。
