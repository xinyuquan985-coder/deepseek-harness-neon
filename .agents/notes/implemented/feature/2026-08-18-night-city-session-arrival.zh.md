# Agent Note: 夜之城会话接入

Status: implemented

[English](2026-08-18-night-city-session-arrival.md) | 中文

## 问题

三个真实工作台获得电影感视觉后，Cyber 的 New Session 页面仍显得空旷。用户要求的启动语音还需要在应用接入时以及每次使用侧边栏 New Session 操作时播放，同时不能让会话创建依赖浏览器媒体策略。

## 决策

**把空白状态视为接入阶段，而不是第四种工作台。** Cyber 专属对话背景使用从已批准概念图派生的干净夜之城画面。它保留城市氛围、接入 HUD 和黑墙操作员，但不烘焙产品文案、侧边栏、输入区或虚假控件。真实的本地化标题和常驻输入区仍位于其上方的既有 DOM 中。

**让动效保持装饰性并兼顾无障碍。** 只有当浏览器未要求减少动态效果时，画面才会缓慢漂移并显示扫描光束。浅色与深色主题继续使用原有空白状态。

**让音频从属于 Session Intent。** 侧边栏持有一份随包发布的 MP3 和一个音频实例。挂载时尝试播放一次启动语音；若被浏览器阻止，则在首次用户交互时补播。点击侧边栏持有的任一 New Session 入口会取消待补播状态、从头播放语音，并立即调用既有 `startSession` 路径。媒体错误会被隔离，不会取消导航或创建会话。

## 曾考虑的替代方案

**把已批准的概念截图直接烘焙到页面中。** 不采用，因为其中重复的侧边栏、输入区和文案会变成不可交互像素，并与实时产品状态逐渐偏离。

**把音频播放成功作为创建会话的前置条件。** 不采用，因为自动播放策略、缺少输出设备和解码失败都不属于会话领域，不能破坏主要操作。

**创建第四个可选择的大厅工作台。** 不采用，因为 A、B、C 继续由真实会话状态自动派生；大厅只存在于尚未选择会话的阶段。

## 结果

每次进入 Cyber 应用时都会获得更充实的夜之城场景，同时保留真实 Workspace 选择器和完整输入区行为。启动音频会在交互前尽力播放；若自动播放被阻止，会保证在首次交互时补播一次；显式点击 New Session 始终会发起自身的尽力播放。媒体打包器现在会把 PNG 和 MP3 资源内联进包产物，因此宿主不需要增加独立静态文件路由。

## 测试

单元覆盖固定了干净装饰素材、本地化标题、启动播放尝试、自动播放补偿、两个 New Session 入口、播放失败隔离和 MP3 打包。包级类型检查与受影响客户端套件覆盖了相关组合。宿主支持的 Playwright 验收会检查正式 Cyber 空白状态、生产图片解码尺寸、真实输入区可见性、铺满几何、减少动态效果降级、页面错误、ARIA 输出和 1920 像素截图。
