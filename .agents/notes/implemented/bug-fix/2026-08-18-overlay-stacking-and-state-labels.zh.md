# Agent Note: 交互浮层脱离功能层叠上下文

Status: implemented

[English](2026-08-18-overlay-stacking-and-state-labels.md) | 中文

## 问题

设置面板和会话标题栏中的子代理目录虽然声明了较高层级，但分别仍是侧边栏和标题栏的后代。这些祖先会创建低于会话正文与吸附输入框的层叠或裁切上下文，因此普通内容能够绘制在两个交互浮层之上。只提高后代自身的 `z-index` 无法让它离开祖先的层叠上下文。

赛博朋克会话标题栏还通过 CSS 伪元素的 `content` 追加 `PTC 模式` 和 `当前代理预设 · DSH_BOOT`。这些文字不随已选择的预设变化，还会重复真实的预设投影，使装饰性文字看起来像应用状态。

## 决策

`ui-primitives` 导出零样式 React 容器 `BodyPortal`，把子节点直接渲染到 `document.body`。设置外壳用它承载既有的全视口浮层。子代理标题栏操作用它承载既有目录树，将目录树改为固定定位，测量真实触发按钮，把菜单限制在视口内，在垂直空间紧张时选择可用空间更大的一侧，并在窗口缩放或捕获到滚动时重新测量。外部点击关闭同时检查触发器子树和 portal 后的菜单，键盘遍历则直接查询 portal 后的目录树。

赛博朋克标题栏不再由 CSS 生成预设或代理名称。预设名称继续由既有、受真实状态支持的 React 贡献负责，不引入替代性的静态文案。

## 备选方案

**提高局部 `z-index`。** 后代无法超过更高祖先层叠上下文中的内容。该方案只会改变数字，不会修正浮层归属平面，仍会复现已报告的遮挡。

**把设置面板和目录改为原生 `dialog` 与 Popover API。** 浏览器顶层能够解决层级，但也会替换已经稳定的焦点、关闭、树导航、视口定位和测试行为。body portal 在保留这些约定的同时修复缺陷。

**保留 CSS 标签，再用更多选择器派生变体。** CSS 无法读取完整的预设投影，这会建立另一个不完整的事实来源。删除伪造标签后只剩一条权威状态路径。

## 后果

- 设置与子代理浮层会显示在会话正文、头像、任务控制栏和吸附输入框之上，无需移动这些功能，也不改变其操作。
- 子代理菜单保留相同的目录行、续接地址、中断授权、外部点击关闭和键盘导航，但其 DOM 父节点现在是 `body`，坐标改为相对视口固定。
- 共享原子组件刻意不提供视觉层或焦点策略；消费方仍负责遮罩、`z-index`、定位和无障碍行为。
- 静态 CSS 不再能够宣称某个预设或当前代理。未来如需标题栏标签，必须来自真实状态支持的 slot。

## 测试

组件测试断言设置浮层和子代理树都 portal 到 body，同时既有关闭、焦点、外部点击与键盘测试继续通过。赛博朋克外壳样式测试拒绝两个伪元素标签。真实宿主的赛博朋克 A 场景使用 `document.elementFromPoint` 检查设置对话框下缘的重叠点和子代理菜单中心，证明最上层命中目标是交互浮层，而不是输入框或会话正文。
