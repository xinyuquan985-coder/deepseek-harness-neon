# Agent Note: Neon 源码检出启动自身产品界面

Status: implemented

[English](2026-08-20-neon-clean-clone-launch.md) | 中文

## 问题

公开的 Neon 源码树包含夜之城样式、人物立绘、三工作台和功能插件，但 Windows 启动器指向了克隆中不存在、被忽略的 `.dsh-runtime` 目录。干净源码构建还会让 Host 侧错峰控制插件在 Host 生成远程模块之前拉入 Client 项目图。即使构建成功，没有主题偏好的新设置文档也会采用上游的跟随系统主题，因此新用户可能只看到标准浅色产品，而不是仓库最重要的界面。

## 决策

Windows 启动器按锁文件安装工作区依赖，运行 `build:runtime`，再从当前检出仓库使用仓库本地 `DSH_HOME` 执行 `pnpm dsh web`。`build:runtime` 先生成 Host 项目引用和 Host 远程模块，再生成除 Vite 所拥有的 `apps/web` 项目外的 Client 项目引用，随后打包两个运行面并通过 Web 应用自身的包脚本完成构建。

Host 侧错峰控制插件引用 `packages/client/ui-offpeak/tsconfig.host.json`。这个配置只包含共享设置与时段入口，因此 Host 生成阶段不会引入 Client 运行时项目图。

`DEFAULT_PREFERENCE` 为 `cyber`。该默认值只在设置文档没有外观偏好时生效；已经保存的浅色、深色、跟随系统和赛博朋克选择仍具有最高优先级，外观设置也仍可在四种选项间切换。

## 备选方案

**提交生成的 `lib` 与 `apps/web/dist` 产物。** 这会缩短首次启动时间，但会同时维护源码与生成产物，扩大每次审查范围，并可能让陈旧 bundle 与当前人物和样式产生偏差。

**继续让启动器指向被忽略的 `.dsh-runtime`。** 私有打包运行时对单台电脑可能方便，但 GitHub 用户无法从源码复现，而且它可能携带与当前检出无关的前端。

**由启动器写入赛博朋克主题设置文件。** 启动时写设置会越过用户对外观的所有权，还会引入启动器专属迁移逻辑。产品默认值既能保留用户显式选择，也不需要制造持久状态。

## 后果

- 干净克隆需要 Node.js 与 pnpm，并在首次启动时安装工作区依赖和执行生产构建，因此比运行预构建产物耗时更长。
- 运行中的 Host 与 Web 资源来自同一个检出版本，所以夜之城资源以及对话、代码、辩论、轨迹、语音、错峰、设置和子代理功能不会悄悄回退到无关的打包前端。
- 新设置文档直接采用赛博朋克主题，已有设置仍保持用户选择的外观。

## 测试

启动器与构建计划测试会拒绝 `.dsh-runtime`，锁定冻结依赖安装与源码启动命令，保留 Vite 对应用外壳的所有权，并强制错峰功能使用 Host 专用项目引用。主题单测覆盖赛博朋克默认值、启动调色板、设置行、Host 注入、持久选择和显式跟随系统行为。干净克隆按冻结锁文件安装、构建全部运行产物、在隔离端口由 `dsh web` 提供页面，并在真实浏览器中展示夜之城背景和黑墙人物立绘。
