# @deepseek-ai/dsh-client-ui-debate-vs

[English](README.md) | 中文

纯浏览器插件：向会话视图环贡献「VS 对决」标签页——`conversation.view` 槽位上的实时辩论看板。由 `debate` 预设组成的会话默认打开本视图（`viewDefaultFor` provide 通道贡献；用户手动选过的标签始终优先）。

看板全部派生自当前会话快照与子代理目录：辩论进行中实时更新，刷新后完整重放。

- **顶部**：辩题（首条用户消息的第一行）与当前回合数（解析主持人战报标题 `# ⚔️ 第 <n> 回合`）；终局后显示「已裁决」。
- **两侧卡片**：正方 / 反方实时状态（未派出 / 进行中 / 已结束，来自子代理目录）；双方子会话中的助手发言按产生顺序实时进入各自卡片，主持人指令与工具过程不展示。
- **主持台**：主持人每回合 VS 战报流（最新置顶，流式 partial 实时渲染）+ 主持人 lane（非战报的主持人回复）。
- **裁判席**：裁判子代理状态与终局判决牌；未裁决时显示「待裁决」。

## 模型体验

无。看板是客户端会话数据的纯展示，不进入任何模型请求。

#### KV Cache 影响

无；本包不组装也不发送任何 provider 请求。

## 已知限制与后续工作

- **识别依赖 debate-arena 词汇**——战报 = 带 `# ⚔️ 第 <n> 回合` 标题的助手消息，判决 = 含「判决牌/获胜方」的消息，双方 = 标题为「派出正方辩手 / 派出反方辩手 / 派出裁判」、以角色名开头或在 `「」` 中声明角色的子代理。其他协议的辩论仍会在主持人 lane 显示主持输出，但不产生双方发言与战报卡片。
- **无深链接**——视图选择只存在于会话视图环内。
- **发言通过轮询更新**——双方卡片每 1.2 秒读取一次对应子会话的历史页；当前最多读取每侧最近 80 条事件。
