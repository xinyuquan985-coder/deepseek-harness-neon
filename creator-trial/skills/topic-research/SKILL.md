# 选题调研（topic-research）

为 AI 自媒体内容（AI 应用开发、软件测评、技术分享、自媒体策划）产出可决策的选题卡。调研的产物是带证据的决策材料，不是素材堆。

## 标准流程

1. **明确输入**：受众（技术向/大众向）、平台（公众号/知乎/B站/短视频）、单篇目标（流量/专业口碑/转化）。不清楚就用 ask_user_question 问用户，不猜。
2. **并行检索**：对每个候选选题并行执行多路 web_search（中英文关键词各一路），记录返回的来源 URL 与关键数据点。热点数字（星标数、下载量、价格）必须来自检索结果或官方页面，不得推测。
3. **本地取证**：选题涉及本地仓库或代码时，用 glob/read/grep 直接取证，引用具体文件路径级别的事实。
4. **竞品与差异化**：检索同类选题的已有内容（媒体文章、视频），判断已有覆盖角度；选题卡必须写明本选题的差异化角度。
5. **输出选题卡**（模板见下），每个选题给 5 项评分（1–5）：受众匹配、素材可得、差异化、时效窗口、涨粉/变现潜力。总分排序，标注推荐与理由。

## 选题卡模板

```markdown
## 选题卡：<标题>
- 一句话定位：
- 受众与平台：
- 证据要点（来源 URL / 文件路径）：
- 竞品内容已覆盖的角度：
- 本选题的差异化角度：
- 风险（时效/事实/立场）：
- 评分：受众_ 素材_ 差异_ 时效_ 潜力_ → 总分 _/25
- 结论：推荐 / 观望 / 放弃
```

## 工具用法

| 场景 | 工具 | 注意 |
| --- | --- | --- |
| 热点与价格检索 | web_search | 每条事实保留来源 URL；价格与版本标"以官网为准" |
| 大规模并行调研 | subagent / workflow | 给子代理完整独立的任务描述；子代理看不到本对话上下文 |
| 本地仓库取证 | read / glob / grep | 引用精确路径；不凭印象陈述 |
| 调研进度管理 | todo_write | 一个候选选题一个 todo |

## 纪律

- 区分"检索到的事实"与"你的推断"；推断必须标注。
- 热度类数字找不到官方口径时写"未见公开口径"，不编造。
- 每轮调研输出至少一张选题卡；没有结论的调研不算完成。
