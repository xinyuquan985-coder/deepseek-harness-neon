# 测评稿起草（review-draft）

按五段结构写测评稿：结论、证据、成本、风险、适用条件。禁止只罗列资料——每个判断都要落到证据上。

## 五段结构

1. **结论**：先说答案。一句话给出"该不该用、用在哪"；给出判断公式或优先级排序，不卖关子。
2. **证据**：逐条证据对应逐条结论。每条证据标注来源：本地文件（精确路径）或 URL。一手取证（亲手跑通、读源码级文档）优先于转述。
3. **成本**：金钱（单价 × 用量的量级估算，标注"以官网为准"）、时间（环境/学习/审稿）、机会成本。给可对照的数字，不写"很便宜"。
4. **风险**：按优先级列，每条配缓解措施。产品处于预览/测试期必须写明破坏性变更风险与版本号。
5. **适用条件**：分环节决策表（环节/结论/适用条件/不适用情形），并给出两周内可执行的行

动方案。

## 证据规则

- 每个事实句后跟来源：`（来源：<文件路径>）` 或 markdown 链接。
- 版本号、价格、订阅档位：写"近似值，以官网为准"，并附官方页面链接。
- 能力边界：先读被测对象官方文档的 Known Limitations 与 FAQ，把"做不到的"写进稿，不写"未来能力"。
- 复现步骤必须是自己（或可信来源）实际执行过的；没跑通的写"未复现"。

## 事实核查清单（交稿前逐项过）

- [ ] 每个结论句都有证据来源
- [ ] 价格/版本标了"以官网为准"并附链接
- [ ] 预发布/实验性状态已声明
- [ ] 与竞品的对比数字来自同一口径
- [ ] 立场披露（如测评自家生态产品）

## 配合

- 信息不足时用 ask_user_question 向用户确认，不猜。
- 长稿用 todo_write 跟踪五个段落，每段写完标记完成。
